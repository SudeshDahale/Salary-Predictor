# Salary Predictor Technical Architecture Guide

## System Overview
The Salary‑Predictor repository is a monolithic, API‑first application built with Python, Flask and scikit‑learn. It serves a static HTML front‑end that collects job attributes, forwards them to a Flask prediction endpoint, and returns a salary estimate generated by a pre‑trained RandomForestRegressor stored on disk. A separate training script consumes the CSV data set, (re)trains the model and persists both the model artefact and its metadata for runtime inference.

## System Layers
### Presentation Layer
**Technologies:** HTML, CSS (inline/assets)

Static client‑side UI rendered from frontend/index.html. Users input job parameters (e.g., experience, education, location) and submit via an HTML form that calls the backend API.

### API Layer
**Technologies:** Python, Flask

Flask application defined in backend/app.py exposing HTTP endpoints (e.g., /predict) that accept JSON payloads, invoke the model for inference, and return JSON responses.

### Model Layer
**Technologies:** scikit-learn, pickle

Serialized scikit‑learn RandomForestRegressor (models/rf_regressor.pkl) together with metadata (models/metadata.json). Loaded at application start‑up for low‑latency predictions.

### Data Layer
**Technologies:** CSV, pandas

CSV dataset (data/Position_Salaries.csv) used for initial training and optional re‑training. Treated as immutable source of truth for model performance evaluation.

### Training Layer
**Technologies:** Python, scikit-learn, pandas

Standalone script backend/train_model.py that reads the CSV, preprocesses features, trains the RandomForestRegressor, evaluates performance, and writes the model artefact and metadata back to the model store.



## Data Flow & Pipelines
1. User loads frontend/index.html in a browser. 2. Form data is serialized to JSON and POSTed to the Flask /predict endpoint. 3. app.py deserializes the request, extracts feature values, and loads the pre‑trained model from models/rf_regressor.pkl (cached in memory). 4. The model computes the salary prediction, which is wrapped in a JSON response and sent back to the UI. 5. UI displays the predicted salary to the user. 6. For model updates, backend/train_model.py reads data/Position_Salaries.csv, retrains the RandomForestRegressor, writes a new models/rf_regressor.pkl and updates models/metadata.json; the Flask service picks up the new artefact on next restart.

## Key Design Decisions
- Monolithic layout simplifies deployment for a lightweight use‑case; all components reside in a single repository.
- API‑first approach isolates prediction logic behind a REST endpoint, allowing future client diversification (mobile, CLI).
- Model artefacts are persisted as files rather than a database to keep the stack minimal and portable.
- Training is decoupled from the serving process; re‑training is performed manually via a script to avoid runtime performance impact.
- Static HTML is served directly from Flask or via a simple web server, avoiding a separate front‑end build pipeline.

## Scalability & Reliability
Current design targets low‑to‑moderate traffic. To scale horizontally, the Flask app can be containerized (Docker) and placed behind a load balancer; the model file can be mounted as a read‑only volume shared across instances. For high‑throughput scenarios, consider exposing the model via a lightweight inference server (e.g., FastAPI or TensorFlow Serving) and storing artefacts in object storage (S3) with versioning. Batch re‑training can be scheduled with CI/CD pipelines to automate model refresh without manual script execution.
