# Salary Predictor

Predict employee salaries using a trained Random Forest model via a simple Flask API and web UI.

## Overview

The Salary Predictor project trains a Random Forest regression model on the *Position_Salaries.csv* dataset, serializes the model, and serves predictions through a Flask API. A lightweight HTML frontend collects user input and displays the estimated salary. The codebase follows a monolithic, API‑first design where the backend (Flask) is the single source of truth for inference, and the frontend consumes its `/predict` endpoint.

## Features

- End‑to‑end pipeline: data ingestion → model training → model serialization (rf_regressor.pkl).
- Flask‑based prediction service (`backend/app.py`) exposing a `/predict` POST endpoint that returns JSON predictions.
- Static HTML UI (`frontend/index.html`) that posts user data to the API and renders the salary estimate.
- Model metadata (`models/metadata.json`) documenting training parameters, feature columns, and evaluation metrics.
- Reproducible environment via `backend/requirements.txt` (Flask, scikit‑learn, pandas, etc.).

## Quick Start

```bash
```bash
# Clone the repository
git clone https://github.com/SudeshDahale/Salary-Predictor.git
cd Salary-Predictor

# Set up a Python virtual environment
python3 -m venv venv
source venv/bin/activate

# Install backend dependencies
pip install -r backend/requirements.txt

# Train the model (produces rf_regressor.pkl and metadata.json)
python backend/train_model.py

# Launch the Flask prediction service
export FLASK_APP=backend/app.py
flask run
# The API will be available at http://127.0.0.1:5000/predict

# Open the UI in a browser
open frontend/index.html   # macOS
# or
xdg-open frontend/index.html   # Linux
```
```

## Architecture

The repository is organized as a single monolithic service where a Flask application (`backend/app.py`) loads the pre‑trained Random Forest model (`models/rf_regressor.pkl`) and serves a `/predict` endpoint. The model is generated by `backend/train_model.py`, which reads `data/Position_Salaries.csv` and stores both the pickle and a JSON metadata file. The static frontend (`frontend/index.html`) interacts with the API via standard HTTP POST, keeping the UI decoupled but still part of the same codebase, reflecting an API‑first approach within a monolith.
